# Travel Agent 插件工作台重设计

状态：交互设计稿，尚未替换正式插件 UI。2026-11-11 用户明确否定原页面的 UI／UX，允许继承技术并要求从头设计；旧版只作为业务功能清单。

已确认：以每日安排为主，点到访联动地图；候选与调整在侧层比较；未知条件贴着受影响的到访或交通段逐项确认，最后统一采用。只重新确认依据或安排实际变化的条件；其他确认保留。确认进度按账号保存到同一云端旅行，换设备／宿主后继续，服务重新校验依据。预算、同行人及完整往返在旅行层审阅。

设计稿使用合成的京都三日旅行，交互仅用于评审；不调用业务 MCP、不代表预订、天气、报价、交通或营业事实，也不构成真实业务验收。本机保存只是设计演示，正式实现须接入上述云端确认规则。地图如包含 OpenStreetMap 几何，仅用于位置与点选联动，路线连接线是示意，不是导航或耗时核验。数据许可及来源记录单独保存在 map-source.json。

需要实际比较：天数切换、到访／地图双向定位、侧层候选比较与试排、就地知悉未知项、局部修改只重确认受影响项、旅行层确认、采用后仍显示缺口，以及窄屏操作。正式方案确定后，才将对应界面接入已有 Java／PostgreSQL 服务。

本机预览：`http://127.0.0.1:5175/?world=ceramic` 为蓝白路书，`?world=lake` 为湖绿日程；页面顶部可切换并重置演示。安装根项目和工作台依赖后，启动使用已有 Vite：`node plugins/travel-agent-openai/workbench/node_modules/vite/bin/vite.js --config design/2026-11-11-plugin-workbench/vite.config.mjs`。桌面与手机实际截图保存在 `screenshots/`；地图截图保留来源标识。

云端服务现在已支持按账号保存确认、按条件依赖失效及采用时重新校验；本设计稿尚未调用这些接口。演示中的本机摘要只用于体验评审，正式界面必须以服务返回的条件与确认状态为准。
