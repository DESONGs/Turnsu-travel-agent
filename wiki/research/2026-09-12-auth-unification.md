# 统一账号、持久会话与账号界面

2026-09-12，以当前实现及本轮验证为准。

## 选择

OpenAuth 可提供共享 OAuth 认证服务，但用户映射与会话管理仍需业务完成；官方 Provider 目录未提供微信、支付宝小程序的原生 code 交换。Better Auth 的默认用户模型要求邮箱，当前微信、支付宝身份没有邮箱，不能为接入框架伪造邮箱。当前只有同一个 Travel Agent 服务边界，因此复用已有平台验证和 `pg`，用 Node 内置 SQLite 支持本地持久开发，没有引入新的认证框架或独立服务。

来源：[OpenAuth](https://github.com/anomalyco/openauth)、[OpenAuth Provider 文档](https://openauth.js.org/docs/)、[Better Auth 数据模型](https://better-auth.com/docs/concepts/database)。这不是新依赖的准入审计。

## 服务与会话

- `auth-channels.mjs` 统一 Google Web、微信 Web/小程序、支付宝 Web/小程序、Apple Web 的配置解析及公开可用性。平台凭据只留在服务端。
- `AccountService` 统一本站账号、已验证身份映射、资料和设备会话。新账号沿用 provider + subject 的旧 userId 算法；显式绑定后，各平台身份指向同一个 userId。已属于其他账号或有旧旅行的身份拒绝直接绑定，不因昵称或邮箱相同自动合并。微信跨端身份一致仍依赖 UnionID。
- 正式登录、开发登录、平台 code 交换及桌面回调均经共同收尾：转移当前游客的旅行和对话、签发新会话、撤销旧会话。开发账号不能绑定真实平台身份。
- 默认会话从实例内存改为数据库随机令牌：仅保存 SHA-256 摘要，账号固定有效 14 天、游客 7 天。生产必须使用共享 PostgreSQL；本地使用权限受限的 SQLite 文件。会话退出、其他设备撤销、解绑相关会话和两分钟一次性授权票据均持久化。
- 绑定需要最近 15 分钟内的真实平台登录，并重新完成待绑定平台授权；票据绑定发起 sessionId，跨会话回调拒绝。至少保留一种登录方式，不能直接解绑本次登录方式。
- Web 保持 HttpOnly Cookie；Electron 主进程使用系统安全存储加密保存 Bearer，按 API Origin 隔离。可信 renderer 在启动请求前恢复令牌。Linux 不接受 `basic_text`；存储失败明确告知仅保留本次应用会话。小程序继续使用现有 Bearer 合同。
- 网络失败不会被误判为会话失效并覆盖原登录，恢复页提供重试。

Apple form_post 继续先以 303 转同站 GET，使 SameSite=Lax Cookie 可用于认领游客数据；只中转 code/state/error，再完成 state、nonce、平台签名验证。

## 账号体验

重设计范围是本次认证上下文中的完整账号体验：登录页/弹层、统一授权按钮、资料页、登录方式页、设备页、操作确认、加载/错误/未配置/过期状态，以及 Web/桌面共享组件。手机布局常驻头像入口，窄屏使用单列账号中心。行程、地图、对话工作区整体重设计不在本轮完成范围内。

资料修改、设备列表、单设备退出、退出其他设备、绑定/解绑均接真实 API。页面不会把未配置平台显示为可以登录；本地开发身份明确标注，不能冒充已验证平台账号。

## 验证与边界

实际隔离 PostgreSQL 16 与 SQLite 均验证了：跨实例读取与撤销、重建 repository 后恢复、令牌摘要、有效期、一次性 code 只消费一次、身份绑定冲突、解绑保护。HTTP 验证在两种数据库下覆盖资料修改、平台身份绑定、发起会话匹配、平台 code 登录同一账号、设备撤销及服务重建恢复。平台响应使用测试替身，不是生产 OAuth 验收。

本地浏览器实际验证了登录、修改称呼、重新载入、手机头像入口、账号三个页面、两个独立 Cookie 会话、退出其他设备后另一端失去登录，以及服务进程停止再启动后同一账号恢复。桌面与手机视口已目测；真实 Electron smoke 验证了系统加密写入、重新读取及清除，并通过既有导航/隔离边界检查。Windows/Linux 和原生小程序未做真机验收。

Google、Apple、微信、支付宝仍需最终 HTTPS Origin、平台应用配置和真实回调验收；未部署。运行 `npm run auth:check` 可检查配置缺口，不能用配置字段代替 live smoke。

升级不导入旧签名会话，以免复活仅在旧进程内记录为撤销的令牌。既有正式账号重登后保留旅行归属；旧匿名 Guest 不自动迁移，应在部署前安排保存。游客 Trip 与 Conversation 转移仍为两个已有 repository 操作，不承诺跨库原子回滚。持久会话不代表旅行 Agent 已支持多实例工作流协调。

生产配置见 [账号配置指南](../current/09-account-configuration-guide.md)。
