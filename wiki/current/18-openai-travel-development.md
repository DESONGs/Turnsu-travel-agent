# Travel Agent OpenAI 主线开发与验收计划

本计划将[技术方案](./17-openai-travel-architecture.md)转成可执行的开发和证据。目标是公开插件目录审核通过并实际发布，随后由新账号验证安装和完整使用。打包、模拟测试或提交审核都不是这个终点。

## 2026-11-11：完整记录与共享交互

[十场景设计稿](../../design/2026-11-11-user-journey-review/README.md)已补齐照片手账、浮雕、目的地沉浸和共享授权的桌面／手机操作，并按用户后续授权替换对应正式 Preact 界面。主规划的整趟方向、每日地图、比较和连带影响仍是独立设计稿，不能据此声称正式插件已完整重设计。

手账可从日期、到访或全旅行开始，允许纯文字和后补地点；照片可增删排序。浮雕为本机预览，明确保存效果后写入同一照片，源图片不变，未保存离开需选择。共享先查找已注册账号，再核对身份与权限影响；查看、编辑、更改权限及撤销均有明确路径。桌面侧层与手机全屏使用相同组件和云端状态。

新增 V17：记录有独立版本、标题、可选到访和更新日期；照片有稳定标识，排序不改变照片身份。写入使用旅行版本、记录版本与幂等请求，当前权限先于回执恢复检查；照片与备注仍仅返回应用展示数据。入口与新工具均已接入同一 Java／MCP／PostgreSQL 链。

真实本机服务的浏览器验证完成两张许可照片上传、保存后整页回读、浮雕保存与原图片比对、排序、共享查看、编辑及撤权后的照片读取拒绝。已修复新应用专用回包未由桥接层读取的问题，并加上生产桥接回归。检查仍使用合成账号和旅行来源；[观察记录与截图](../../design/2026-11-11-user-journey-review/screenshots/media-observations.json)区分设计预演和服务结果。Google、真实宿主、物理手机及来源授权尚未验收。

插件、原生清单与工作台更新为 `0.5.0`，部署须先构建新 UI，再使用带 V17 的 Java JAR 执行正常 Flyway 升级。正式域名、Google 项目、模型额度和旅行来源授权仍未准备。下面保留前序技术验证，旧页面截图不作为本轮视觉认可。

## 2026-11-11：按账号继续逐项确认

云端确认服务和现有插件读写链已接入 V16。确认依赖由 Java 生成，账号进度独立保存；已确认且依据不变的项在草案编辑、预算修改、相同事实重新查询及重新打开后保留。两窗口并发保存会明确提示同步，迟到的旧条件不能覆盖当前记录；已取消的勾选也不会被旧回执重放。撤权后不能读写进度，且不能借用同行人的确认采用。这个技术接线仍使用用户已否定的页面布局，不代表新 UI 已通过评审。

已通过真实 PostgreSQL 和 MCP HTTP 的保存、重开、局部失效、账号隔离、并发及撤权回归。实际编译工作台还完成了“勾选两项 → 关闭并整页重开 → 只恢复这两项 → 完成其他确认 → 采用并重开”的操作，并复查暂定状态和跟进缺口；账号和上游资料仍为合成输入。技术截图：[已保存的确认](../research/assets/2026-11-11-review-progress/saved-cloud-review.jpg)、[采用后重开](../research/assets/2026-11-11-review-progress/reopened-tentative-plan.jpg)。界面脚本增加 `resumePartialReviewAfterReload(tab)`，其余隔离运行方式见文末。真实设备、真实宿主及 Google 登录仍待外部配置和验收。

## 2026-11-10：宿主与合同迭代

本轮修复 Codex 精确登记的本机 OAuth 回调被拒、切换账号后旧资料残留、未关联对话仍可发送请求，以及迟到文件覆盖当前旅行。对应行为回归先复现失败，再在修复后通过。浏览器协议夹具实际复验了清理旧资料、无关联时只保存请求、关联后单次发送、文件打开顺序及撤权后的清理。夹具使用合成账号与资料，不是 Google 或原生宿主验收。

标准 MCP 和 OpenAI 现在分别构建、发布带摘要的 UI；组件合同由一个文件供 Java 和前端消费。可选组件按保存顺序渲染，类型或版本不支持时保留资料并显示原因；服务也拒绝重写不兼容组件。插件候选仅包含清单、Skills、许可证和构建摘要；原生包还包含明确的本机回调配置，不再打包旧客户端或开发依赖。工作台与两种插件清单版本统一为 `0.3.0`。最终 Java JAR 已重新构建，检查确认包含两份匹配摘要的页面和同一组件合同，且不包含旧 `ui/index.html`。

[最终界面截图](../research/assets/2026-11-10-host-contract/mcp-verification.jpg)保留了协议夹具标识和未核实条件。可复用的界面验证脚本位于 `plugins/travel-agent-openai/workbench/tests/browser-acceptance.mjs`：通过 `cua_repl` 绑定夹具页面后，分别调用 `verifyOpenAiHost(tab)` 与 `verifyStandardHost(tab)`，前者覆盖账号／撤权清理、文件顺序和关联后单次发送，后者覆盖标准页面的核验展示；在 `?host=mcp&order=places-first` 页面传入 `{ placesFirst: true }`，还会核对[保存的可选组件顺序](../research/assets/2026-11-10-host-contract/mcp-component-order.jpg)。它们不替代真实宿主验收。

后台结构化到访建议可原子地保存为同一旅行的未采用草案。来源、旅行版本或执行代次不成立时拒绝；用户可查看核验结果。当前核验只覆盖来源有效性、到访时间和已记录交通的关系，其他关键条件明确标为未核实；正式采用、持续跟进、地图及完整交通链仍待后续接线和真实来源验证。

## 当前状态

当前在隔离分支开发，原工作区的既有修改和旧数据保留。新 Java 服务已开始实现：隔离 PostgreSQL 存在账号、旅行、访问权限和 OAuth 表；MCP 可以创建、分页读取、共享及撤销旅行，尚无正式安排时需求可以带版本与幂等标识修改。工作台可编辑预算上限与币种；交通价格有明确范围的部分可按原币种汇总，尚未完成完整费用归集、汇率和全行程预算核验。可逐人保存出行需求，更新一人时保留其他人和未修改的要求；用户可在工作台确认移除一名同行人或其中一项已支持的要求。已有正式安排的需求修改会明确拒绝，直到旧规划规则完整迁入。

实现了 OAuth 发现、动态客户端注册、PKCE 授权码、令牌轮换与撤销、浏览器绑定的 Google 授权入口和同意页面；已实现高德天气和地点检索的受控接入，以及有权限、版本和过期标记的来源结果引用。地点检索保留分页与不完整记录的数量，地图记录不等于营业、库存或预订报价。隔离测试使用测试身份和模拟来源返回，**没有完成真实 Google 登录、真实天气／地点来源或宿主接入验证**。高德[公开协议](https://lbs.amap.com/pages/terms/)对商业使用及资料存储有约束；[接入审计](../research/assets/2026-11-06-openai-amap/amap-third-party-audit.json)为阻止启用状态，在确认许可覆盖当前保存、展示和助手使用方式并完成真实隔离 smoke 之前，保持高德来源关闭。

Cirium 航班状态已有默认关闭的只读适配器：需要用户明确提供承运人、班次、出发机场与当地出发日期，返回的多个结果均保留并需由用户核对；空结果、来源不可用和没有变化不能混为一谈。查询结果带旅行权限与有效期，不能证明预订或自动启用跟进。[接入审计](../research/assets/2026-11-06-openai-cirium/cirium-third-party-audit.json)仍为阻止启用状态；订阅、数据许可、真实调用及持续跟进均未完成。

高德步行路线查询已接入 MCP 的受限查询路径：起终点只能来自同一旅行的有效地点引用，保留来源返回的路线数量与不完整项；检查后旅行版本变化或访问权限撤销会阻止迟到结果保存。可将用户指定的一条路线估算与草案中相邻到访的时间间隔比较，但不会保存路线选择或确认整趟旅行。结果是查询时的估算，不能证明未来路况或连续无台阶；结果的有效期不超过任一起终点来源。该适配器同样默认关闭，尚无来源许可和真实调用；公交、驾车、跨城及草案逐段路线核验仍未完成。

Preact 工作台现可从本机 MCP 宿主模拟器读取旅行列表、打开空旅行、显示旅行要求及已绑定的地点查询页；添加新页会保留已有页，过期或读取失败的页分别标明。用户可以固定、隐藏和恢复这些可选组件；保护后的新地点结果会保存为待确认，用户可加入或忽略。地点组件目前最多绑定 128 个来源页，逐页移除功能尚未实现。

新服务已能保存有来源引用的行程草案，保留同一地点的独立到访，按每次到访的 IANA 时区识别时间重叠和夏令时异常，并检查地点的旅行类型是否与安排角色相符；工作台可显示、修改单次到访的时间及忽略草案。草案使用独立版本，修改后对应的旧助手请求失效。工作台请求先保存，再尝试通知宿主；服务分别记录宿主回执与助手接收，发送状态未知时提供可复制的恢复内容，不自动重发。以上交接只在本机模拟宿主验证，真实宿主关联对话和回执仍未验收。地点时区、往返交通、营业、预约、库存、预算和同行人限制尚未完整核验。用户可按上方规则逐项确认后采用暂定行程并查看每日安排；地图、完整试排及已核验采用仍未完成。文件格式已按 SDK 检查，真实宿主文件入口仍未验证。

去程、返程和跨城交通要求可分别保存方向、日期及需要规划／自行安排的范围，并在工作台查看；修改或移除一段不会覆盖其他段。它们只是需要处理的要求，不是已找到的班次或已验证的交通链。工作台可由用户确认记录多段已订交通，分别保存出发、到达的当地时间、IANA 时区、UTC 偏移和乘坐人；保存、修改或移除一段会保留其他段。用户可记录交通价格的原币种、整笔／每人计价、税费状态和覆盖范围，金额按十进制字符串保留；仅汇总明确属于单段的价格，多段共用或范围不明的价格不自动计入。按已记录人数计算的同币种部分已超过预算时会提示；其他费用和外币尚未换算，不能声称全程预算已核验。不同交通同时进行时，系统区分相同乘坐人、乘坐人未知以及已知不同乘坐人；前两种需要核对，最后一种不会误报。草案会提示到访时间可能与已记录交通重叠，但因为到访还没有乘坐人归属、也可能描述交通本身，这只是需要人工核对的提醒。记录只代表用户提供的事实，尚未接入班次、出票状态或票价核验，也没有完成衔接及往返完整性的自动校验。形成正式安排前，可以修改预算和同行人要求并保留已订交通；已订交通存在时，交通要求、目的地等其他范围仍需完整影响检查，不能直接修改。已登记为乘坐人的同行人需先从对应交通中移除，才能从旅行中移除。

分享方式已按用户确认调整：输入对方 Google 登录邮箱查找，确认对象与查看／编辑权限后授权，可修改权限和撤销。账号使用 Google `sub` 维持身份，邮箱只作定位；原文不放入模型可见结果。隔离宿主测试已覆盖权限调整和撤销，真实 Google 登录、真实宿主对应用专用工具及展示数据的隐私隔离仍未验证。用户选择允许所有 Google 已验证邮箱；非 Google 托管的邮箱在确认界面提示再次核对。

照片手账和目的地体验的最新状态见页首。本轮已解除新建记录对候选有效期与照片数量的依赖，保存后还能编辑照片与效果；每条最多三张、每趟最多四十条。记录、图片与效果执行同一旅行权限检查，记录与二进制分表。浮雕和风格化三维场景不代表扫描、现场情况或已核验路线。

后台任务的 PostgreSQL 保存、配额、接管代次、撤权和过期租约恢复已有实现；工作台可重开任务进度、查看未采用的建议及取消任务，旅行要求变化后会标明旧研究需要重查。Pi 执行器经受限 HTTP 读取旅行、天气、地点、步行估算及明确航班状态候选，重复查询可复用有效检查点；接管后迟到的航班或步行来源结果不会保存，地点引用失效时步行结果也不会继续复用。这里只通过隔离 HTTP 与模拟模型、来源验证，航班候选不能证明预订或启用监测。真实 OpenAI 模型、完整规划工具及生产安全尚未验收，后台委托默认关闭。完整组件、旅行规则、除目的地天气外的持续跟进、目的地场景与路线联动和公开发布均未完成。

## 开发与验收细则

1. **状态迁移：**逐条对照旧 Trip、到访、交通、预算、候选、证据、锁定和采用行为，在 Java 服务内实现；用同一输入比较旧规则和新结果，再以新服务的真实入口和 PostgreSQL 验证。保留预算变化、多次到访、局部换酒店、已订交通事实、候选数量和刷新恢复回归。

   已发现旧 `completeItineraryIssues` 将餐次时间固定按 UTC+8 计算；迁入全球旅行时必须按每次到访的 IANA 时区判断，并覆盖跨时区和夏令时，不能把旧结果直接当作正确答案。
2. **版本及身份：**账号只能读取自己拥有或被分享的旅行；viewer 不能写，editor 不能替所有者分享。写入必须检查预期版本、幂等键和锁定项。文件、媒体和结果引用同样做权限检查。角色撤销后后续操作不能继续。
3. **规划与跟进：**采用操作原子地保存计划及跟进范围。检查无变化不调用模型；来源不可用、超出窗口、没有变化分别记录。后台建议不得修改采用版；前台接管提升执行代次，旧结果被拒，受影响的只读检查继续。
4. **宿主与工作台：**先连接并展示真实旅行，组合已注册组件；用户的固定、修改和删除不被迟到结果覆盖。发送助手请求先持久化，再通知；回执未知可恢复、不自动重发。真实宿主逐项验证全局、对话、文件、关停重开和多实例；桌面、网页及手机实际操作。
5. **安全与数据：**新 Provider 保留固定 SHA、许可、维护状态、依赖和写面审计；小红书和抖音限独立 Worker 三个只读操作。媒体需要实际压缩、去除 EXIF、权限和容量检查。令牌、证件、支付、手机、Cookie 和浏览器 profile 不进入模型、日志或成果。需要覆盖中文与英文输入，过滤规则本身不能证明全面防泄露。
6. **容量与恢复：**500 个账号、每账号两个 UI 实例模拟读取、操作、重连和提交；独立测真实后台执行和上游额度，不能用在线连接数代替规划能力。验证队列上限、重复点击、API/Worker 中断恢复、备份恢复和重新授权。按实际负载报告服务内任务接收 p95/p99、错误率和来源瓶颈。
7. **审核与发布：**提供稳定 HTTPS MCP 入口、版本一致的 UI 资源和插件包；准备专用审核账号、资料、成功与失败用例及演示，按实际反馈整改。上线后新账号完成安装、连接、采用、查看变化与确认调整，再记录发布结果。

## 本地新服务

服务目录为 `services/travel-service/`，使用 Maven 和 Java，Flyway 在空 PostgreSQL 上建立结构。服务与 Worker 的配置示例分别在各自目录的 `.env.example`，实际值需导出到进程；示例文件不会自动加载。工作台目录为 `plugins/travel-agent-openai/workbench/`，执行 `npm ci --ignore-scripts`、`npm run build` 与 `npm test`；Pi 执行器目录为 `services/planning-worker/`，执行 `npm ci --ignore-scripts` 和 `npm test`。之后在服务目录执行 `mvn -Dtravel.ui.required=true -Dtravel.pi.required=true test`，可连同 MCP UI 资源和 Pi HTTP 接线一起验证。没有构建 UI 时服务不会注册工作台入口。当前测试使用本机临时 PostgreSQL，不触碰旧数据库；需要能在本机开启临时端口。不得将隔离测试中的模拟 Google 身份、模拟天气、模拟模型和旧版本 Provider smoke 表述为真实登录或完整业务验收。

两个插件清单与工作台握手版本目前一致为 `0.5.0`，构建时直接读取工作台包版本并有合同检查。Java 服务以自己的版本号构建；正式发布需固定插件、UI 和服务的兼容组合，当前版本号不代表已发布。

## 新主线的构建与插件候选

在仓库根目录运行 `npm run mcp:build`，或在 `plugins/travel-agent-openai/workbench/` 运行 `npm ci --ignore-scripts`、`npm run build` 和 `npm test`。服务构建会读取两份页面、摘要和共享组件合同；正式候选应使用 Maven `clean package`，避免旧构建残留。服务测试命令仍为 `mvn -Dtravel.ui.required=true -Dtravel.pi.required=true test`。`npm run mcp:serve` 启动新 Java JAR；旧 TypeScript 代码仅作迁移对照，不在本次插件候选中交付。

以下地址仅为格式示例，不能直接安装到真实服务：

```sh
# ChatGPT / 公共 Agent Plugins 候选
npm run plugins:pack -- --origin=https://travel.example.com --out=/absolute/path/to/empty-portable-candidate

# Codex 原生候选：先将完全相同的回调登记在服务白名单
npm run plugins:pack -- --origin=https://travel.example.com --format=codex --callback-url=http://127.0.0.1:4321/callback/registered --callback-port=4321 --out=/absolute/path/to/empty-codex-candidate
```

目标目录必须为空，以免混入其他版本。打包器会生成同名 ZIP；它不会部署服务、创建 Google 项目或提交审核。实际域名、回调地址、Google 配置、来源授权与模型额度仍需准备和验证。

`scripts/workbench-browser-fixture.mjs` 启动仅监听本机的协议夹具，地址打印到终端。它加载实际构建页面，用合成账号、来源与发送回执重放界面行为；标准页面可通过 `?host=mcp` 打开。该夹具没有真实 Google、模型或旅行来源，不是生产启动命令。已有测试保护包内容白名单、回调配置、HTML 摘要、组件一致性、账号切换、权限失效、文件竞态及未关联对话的拒绝发送。

## 暂定采用的隔离浏览器复验

先构建工作台，在 Java 服务目录单独运行：

```sh
mvn -Dtravel.browser.fixture=true -Dtest=McpHttpIntegrationTest#manualTentativeWorkbenchWithRealService test
```

测试使用临时 PostgreSQL，最多保留 12 分钟，并打印私有 `connection.json` 路径。文件只包含隔离测试连接，权限为 `0600`；不要复制到文档、日志或插件。保持 Java 进程运行，在仓库根目录执行 `node scripts/workbench-service-fixture.mjs /实际打印的路径/connection.json`，再用 `cua_repl` 打开该脚本打印的本机地址。页面及工具来自实际 Java MCP 服务，登录身份、地点和天气明确为合成；代理不把测试令牌发送给浏览器。

`plugins/travel-agent-openai/workbench/tests/tentative-browser-acceptance.mjs` 提供三个顺序执行的界面检查：`reviewTentativeItinerary(tab)`、`adoptAndReopenTentativeItinerary(tab)`、`checkWeatherAndPause(tab)`。需要从全新夹具运行；检查逐项确认门槛、保存后重开、天气变化依据和暂停。结束时在私有连接文件同目录创建空 `stop` 文件，Java 会核对暂定状态及天气事件，再关闭临时数据库并清除连接文件；最后停止 Node 代理。该测试没有真实 Google、模型或上游授权，不能作为真实宿主或生产验收。

`TRAVEL_FOLLOW_UP_SCHEDULER_ENABLED` 默认 `true`，仅控制跟进调度，不会开启默认关闭的来源。HTTP 与浏览器隔离测试显式关闭自动调度，天气按钮只触发测试来源响应与同一正式跟进执行方法。实际部署保留正常调度，并先完成来源授权、配额与真实 smoke。
